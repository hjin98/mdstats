# MLFF documentation history

This tree records **non-normative completed lineage**. Current scientific, execution, API, persistence, and workflow authority lives in `docs/arch_manuals/mlff_training_data_architecture.md`, `docs/arch_manuals/mlff_training_data_dependency_graph.json`, and `docs/specs/training_data/`.

Active proposed transitions and developer implementation gates are not history and are not current product authority; they live under repository-root `workplans/active/` until accepted or abandoned.

- `LINEAGE.md`: era-level map of code-development history and index ownership.
- `architecture_revisions/`: historical architecture revision notes; see its `INDEX.md`.
- `release_notes/`: release and hotfix deltas; see its `INDEX.md`.
- `manual_snapshots/`: selected historical current-authority snapshots retained for provenance, including the pre-DOC-GOV1 mixed MLFF authority surfaces.
- `legacy_rendered_artifacts/`: rendered historical artifacts that lack a canonical current source role.
- `legacy_root_documents/`: retired parent-level reports retained for lineage rather than discarded.

When accepted software changes current structure or behavior, update the owning architecture/specification first and then record the completed delta here or in release history. Do not prepend revision commentary or completed developer-gate logs to current architecture/specifications. Historical snapshots never regain normative authority merely because a current file links to them.
