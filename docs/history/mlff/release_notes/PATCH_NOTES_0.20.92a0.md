# mdstats 0.20.92a0 patch notes

## Evaluation / verification CUDA estimator default

The five-minute, single-job CUDA calibration and fixed post-calibration concurrency
policy are retained. The robust upper-band estimator is shifted upward because the
0.20.91a0 default (discard the highest 10%, average the next 10%) was slightly
underestimating sustained evaluation/verification demand on the real campaign.

After the independent 1% activity filters, the new default now:

1. sorts GPU-utilization and incremental-VRAM samples independently;
2. discards only the highest 5% of retained samples;
3. averages the next-highest 10% of retained samples;
4. therefore targets approximately the 85th--95th percentile band for normal
   sample counts;
5. freezes these estimates for the remaining queue exactly as in 0.20.91a0.

This moves the estimate upward while still removing the most extreme transient
kernel/allocation peaks. Live GPU-utilization spikes remain diagnostic only after
calibration. The live VRAM hard guard remains active.

## Backward compatibility

New generated TOMLs use:

```toml
inference_gpu_calibration_peak_trim_fraction = 0.05
inference_gpu_calibration_band_fraction = 0.10
```

The exact shared `0.10` peak-trim value generated by 0.20.91a0 migrates to the new
`0.05` default when read by 0.20.92a0. Explicit phase-specific peak-trim values
remain authoritative, and other custom shared values are preserved. The historical
0.20.90a0 `*_gpu_calibration_upper_tail_fraction` compatibility alias for band width
is unchanged.

Training, CPU evaluation/verification, scientific evaluation identities, checkpoint
selection identities, verification identities, and cached scientific records are
unchanged.
