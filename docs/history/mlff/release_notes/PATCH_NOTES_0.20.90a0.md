# mdstats 0.20.90a0 patch notes

This release tightens CUDA resource estimation for MLFF evaluation and bounded NVE
verification without changing scientific identities or training scheduling.

- The initial CUDA concurrency remains exactly one job.
- The campaign-wide calibration window increases from 180 seconds to 300 seconds.
- Incremental GPU-utilization and VRAM samples below the existing 1% activity floor
  are still discarded independently.
- The estimator no longer averages every retained sample. It sorts each retained
  metric independently and averages only the highest 10% (`ceil(0.10*N)`, minimum
  one sample) to capture burst demand conservatively.
- GPU and VRAM upper-tail sets are independent because their peaks can occur during
  different evaluation/verification stages.
- The resulting upper-tail means become the fixed per-job estimates for the
  remaining queue. Live post-calibration telemetry still throttles replacements if
  aggregate GPU utilization or VRAM actually reaches the configured ceiling.
- New configuration: `inference_gpu_calibration_upper_tail_fraction = 0.10`, with
  `evaluation_...` and `verification_...` phase-specific override forms.
- The exact shared 180-second default generated by 0.20.89a0 migrates to 300 seconds.
  Explicit phase-specific values and other custom shared values remain authoritative.
- CPU evaluation/verification remains on 20 seconds; training remains on 60 seconds;
  CPU/GPU/VRAM ceilings remain 90%; RAM remains 80%.
