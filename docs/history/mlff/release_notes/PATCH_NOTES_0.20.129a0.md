# mdstats 0.20.129a0 patch notes

## Multi-head-only generated campaign default

The seven-gate adaptive MLFF revision remains closed exactly as implemented through
ADAPT-MIGRATE1 in 0.20.128a0. This release changes only the **initial campaign
training matrix** generated by `init`; it does not alter adaptive stopping, ranking,
full evaluation, verification, monitor membership, score thresholds, or learned-model
precision semantics.

### New default matrix

New configurations enable only `[training.multihead_replay]` and use four optimizer
seeds `[1, 2, 3, 4]`. Every seed receives three cross-validation folds plus one
final-development fit, producing `4 x (3 + 1) = 16` multi-head training jobs for the
default `n512` selection size. All seeds share the same fold-partition seed so fold
membership is paired across optimizer seeds.

`[training.naive_fine_tuning]` remains present in generated TOML as an explicit
comparison/ablation surface, but `enabled = false` by default. Its example seed array
is also `[1, 2, 3, 4]` so enabling it produces a directly paired comparison unless the
user edits the matrix.

### Compatibility

Existing campaign TOML is not rewritten. Explicit nested method tables retain their
frozen values, and historical shared `modes`/`seeds` configurations remain readable.
The parser's legacy implicit fallbacks are intentionally unchanged so upgrading mdstats
does not silently expand an old campaign that omitted optional seed fields.
