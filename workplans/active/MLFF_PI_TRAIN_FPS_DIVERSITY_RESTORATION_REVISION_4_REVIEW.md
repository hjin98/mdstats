## 1. Review question

## 2. Historical reconstruction result

PASS.

The recovered history establishes that the direct DATA7 selector is the older generation and that the later production path was:

```text
DATA7 fitted subset-input evidence
 -> FEAS1
 -> MVIDX1
 -> MVSEL2
 -> MVSTATE2
 -> REPAIR2
 -> MVQUAL2
```

The mature selector evolution specifically retained exact scientific ranking while replacing eager/inverse state with candidate-forward sparse rows, exact staged filtering, certified lazy representative selection, compact continuation state, exact repair and independent qualification. The pre-P6 source tree still contains the mature production engine and confirms that the failed PAR1 candidate-thread path had already been removed.

No evidence reviewed shows that MVSEL2 was retired because its coverage/diversity method failed. P6 removed it as part of the broader destructive V7 topology cleanup.

## 5. Coverage criterion

PASS.

Revision 4 corrects a material weakness in the earlier plans: MVQUAL is restored as an **independent hard membership-admissibility check**, not only as a dashboard diagnostic.

The plan restores historical `0.95` hard-family coverage as the default current candidate-qualification threshold unless exact D1/D2 reconciliation finds a concrete current incompatibility. It keeps coverage/support qualification separate from model accuracy: EVAL2/CV still govern model behavior.

This matches the protected requirement that each candidate training size must be a sane, coverage-satisfying dataset before model-behavior comparison is meaningful.

## 6. MVSTATE2 and REPAIR2

PASS.

Both are compatible with the current one-order architecture after rebinding.

MVSTATE2 stores compact exact continuation state rather than candidate marginals or lazy-heap caches. Rebinding its historical label-domain identity to current P_train/split/input identities is straightforward and preserves restartability without creating a second campaign currentness owner.

REPAIR2's historical active-shell, protected-lower-prefix, rank-inheritance and no-hard-coverage-regression behavior is already consistent with one repaired master order. Revision 4 correctly adapts only shell boundaries from the fixed historical universe to current configured candidate sizes.
