# Active workplans

Active workplans are temporary engineering coordination and do not define current mdstats behavior by themselves.

There is one active MLFF implementation workplan:

- `MLFF_TARGET_SIZE_TRAINING_PRIORITY_EVALUATION_LADDER_ARCH_RESET_WORKPLAN.md` — V7 final transition freeze. Target-size is a one-dimensional convergence experiment in training cardinality `N`. Electronic-structure provenance is recorded precisely but compatibility grouping is advisory and is removed from current training eligibility, canonical label identity, neutral partition identity, and target-size authority. One neutral target population is split into training and exact evaluation reserve; one deterministic `pi_train` and one frozen `M1/M2/M3` ladder feed the exact `n1/n2/n3` screen. Deterministic preparation is common across all candidates; stochastic training is paired with the same two ordered optimizer seeds across every `N`, with no adaptive seed expansion. CV is a separate post-selection methodological-validation experiment built only from frozen `T_selected`. The transition is explicitly staged: build/test neutral and V7 components while inactive, perform one atomic current-runtime/persistence cutover with no V5 fallback or dual authority, then destructively remove the retired label-domain/CV/per-domain FEAS/MVIDX/MVSEL/REPAIR/MVQUAL/complement topology while retaining useful optimized kernels behind the new owners.

All earlier target-size architecture-reset/scientific-simplification revisions are superseded by V7. Full long real-data/GPU production qualification remains separate and deferred to final release. Scientific M-ladder decision-preservation qualification is reported separately and may be `deferred/unavailable` when representative evidence is unavailable.
