# Incremental Documentation PDF Autosynchronization

## Objective and protected concerns

Replace the architecture-only documentation CI with one repository-wide publication path. A pushed Markdown change on any branch must rebuild and republish only tracked PDF publications affected by the changed authoritative Markdown source graph. Preserve direct `X.md -> X.pdf` publications, the composite MLFF chapter -> assembler -> assembled Markdown -> PDF authority chain, deterministic generated bytes, failure atomicity, same-branch writeback, and correctness under rapid/concurrent pushes. Nonpublication Markdown must remain Markdown-only.

Implementation and real Actions validation occur first on `ci/incremental-doc-pdf-autosync`, created from the then-current tip of `fix/target-size-exact-boundary-screening`; final delivery is a PR back to that target branch after re-resolving/reconciling its latest tip.

## Frozen design

- `docs/build_pdfs.py` is the single generalized publication planner/renderer.
- Existing tracked sibling `*.md`/`*.pdf` pairs are inferred direct publications. A new first-time publication or nontrivial graph is declared in `docs/pdf_publications.json`; not every Markdown file is a PDF target.
- MLFF canonical inputs remain the ordered chapter files under `docs/arch_manuals/mlff_training_data/`; `tools/build_mlff_architecture_manual.py` remains the real assembler; `mlff_training_data_architecture.md`, its PDF, and existing manifest are derived descendants.
- Incremental planning uses rename-aware final-tree Git delta and both before/after trees. Adds, modifications, deletions, renames, nonancestor/force-push ranges, and zero-before branch creation must fail safe; delete/rename cannot leave a known stale PDF.
- Tracked `docs/**.pdf` files are canonical generated repository outputs. Rendering is attempt-local, validated, then atomically replaces tracked targets. Failed render leaves the prior PDF untouched.
- Normal Markdown changes rebuild only affected publications. Builder/workflow/publication-map/renderer/assembler changes deliberately run a full publication-consistency build.
- Workflow push trigger applies to all branches; generated PDF-only bot commits do not recursively rebuild. `workflow_dispatch` provides recovery/full rebuild.
- Toolchain identity is immutable/verified. Identical source and renderer state must produce byte-identical representative PDFs before unattended writeback is accepted.
- Do not use lossy `cancel-in-progress`. Each run builds from its event commit, then revalidates each publication's source/build fingerprint against the current remote branch before applying output. Newer same-target source invalidates the older output; disjoint outputs may reconcile; unrelated branch advancement must not discard a valid publication. Retries are bounded and only for demonstrated non-fast-forward races.
- Bot stages only builder-declared generated paths and writes to the same branch with minimum `contents: write`. Git authorization rejection must be reported as publication failure; never weaken branch protection.
- Preserve `docs/build_architecture_pdf.sh` only as a delegating compatibility wrapper if useful; it must not retain independent rendering semantics.
- Non-Markdown resource invalidation is outside the requested Markdown trigger unless inspection proves an existing publication materially depends on such a resource; reopen only that invalidation surface if evidence requires it.
- No mdstats scientific/runtime behavior change and no production-scale qualification are part of this work.

## Implementation obligations and acceptance

1. **Planner/publication model.** Discover direct pairs; support explicit first publications and composite definitions; expose changed-range, changed-path, full, target, dry-plan/machine-readable behavior. Tests: one direct, two direct, nonpublication Markdown, explicit first publication, composite dependency.
2. **Git transitions.** Use before/after tree state for delete/rename and final snapshot semantics. Tests: delete stale PDF, rename pair, rename to nonpublication, zero-before full path, nonancestor before/after.
3. **Composite MLFF owner.** A canonical chapter change must execute the real existing assembler before rendering the composite target and preserve manifest/provenance. Test through actual repository/Actions path; test-side concatenation is not acceptance.
4. **Transactional rendering.** Render temporary output, verify success/nonempty, then atomically replace. Deterministic renderer failure must prove old PDF bytes remain unchanged.
5. **Reproducibility.** Pin renderer source identity and record versions; rebuild representative direct + composite targets twice and compare bytes. Unexplained broad binary churn blocks acceptance.
6. **Workflow.** All-branch push + manual recovery; full history checkout; incremental normal build, full infrastructure build; upload build evidence; same-branch bot commit; no unrestricted `git add -A`; no recursive generated-output loop.
7. **Stale-write correctness.** Re-fetch current branch immediately before publication. Compare per-target source/build fingerprint; skip stale same-target output, accept unchanged-fingerprint output across unrelated advancement, and allow disjoint targets to converge. Real temporary-branch tests must cover rapid same-target, rapid disjoint-target, and documentation push followed by unrelated branch advancement.
8. **Authorization truth.** Build success and repo publication success are distinct. A rejected bot push is visible and not reported as synchronized; retain build artifacts when practical.
9. **Documentation.** Update only durable documentation that owns how PDF publication is discovered, declared, run locally, and synchronized. Do not put gate chronology into permanent manuals.
10. **Final reconciliation.** Re-derive affected surface, rerun focused/affected regression, real Actions integration, and a full consistency build. Remove temporary test edits. Re-fetch target branch; reconcile any advancement and rerun invalidated acceptance before PR.

## Material stages

### G0 — Baseline/ownership

Resolve latest target tip; create temporary branch; inspect old builder callers and publication/source graph. Close only when no competing build authority remains unresolved.

### G1 — Local publication engine

Implement planner/config/transactional renderer and focused tests. Close on planner regression, real MLFF assembler integration, renderer failure atomicity, and deterministic representative rendering. Automatic writeback is blocked until determinism is established.

### G2 — Real workflow/writeback

Generalize Actions and exercise actual temporary-branch direct and composite Markdown pushes. Close when exact affected PDFs are rebuilt, bot writeback works, unrelated code does not trigger docs build, and generated output does not recurse.

### G3 — Concurrency/reconciliation

Exercise overlapping disjoint and same-target pushes plus unrelated branch advancement. Close only when no affected publication is lost and stale output cannot overwrite newer source.

### G4 — Final candidate

Remove transient markers/fixtures, run final full consistency and affected regression, reconcile to latest `fix/target-size-exact-boundary-screening`, and confirm only intended implementation/generated consequences remain.

### G5 — PR

Open `ci/incremental-doc-pdf-autosync` -> `fix/target-size-exact-boundary-screening`. PR records final base SHA, regression/integration evidence, renderer determinism, real Actions writeback/race evidence, full consistency result, and any branch-policy limitation. Do not auto-merge.

## Implementation authority

**Delegated:** Python internal decomposition, exact JSON schema/CLI spelling/report shape, temp-directory mechanics, bounded retry count, test-file layout, and whether the compatibility wrapper remains, provided frozen semantics survive.

**Reopen only on evidence:** materially heterogeneous renderer requirements; nondeterministic PDFs; proven non-Markdown resource dependencies; branch policy fundamentally preventing required same-branch writeback; GitHub event semantics unable to support lossless optimistic reconciliation; a supported external contract incompatible with wrapper delegation; or another generated-document authority outside the direct/composite model.

## Handoff closure

The required chain is:

```text
pushed branch delta
 -> identify authoritative changed Markdown/build inputs
 -> select exact direct/composite publications
 -> render and validate transactionally
 -> compare event publication fingerprints with current remote tip
 -> apply only non-stale generated outputs/deletions
 -> commit to same branch when authorized
 -> prove with focused regression + real Actions orchestration
 -> reconcile latest target branch
 -> PR back to fix/target-size-exact-boundary-screening
```

The workplan is the minimum known contract, not a ceiling. Newly discovered necessary local consequences that preserve these frozen semantics are incorporated and tested; only evidence-backed redesign may change a frozen decision.
