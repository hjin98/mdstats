## 4. One current resource/scheduling authority

Current main still retains `mdstats.training_data.resources` and `StageResourceScope`; P6 deleted `work_queue.py`. Revision 7 therefore requires **reuse + restoration**, not a new scheduler family.

### 4.1 CPU budget

Let `N_available` be runtime CPU availability after affinity/cgroup constraints. The campaign resource owner computes the current budget. For the historical/default production fraction:

```text
B_cpu = max(1, floor(0.90 * N_available))
```

where current configuration may explicitly choose another accepted `cpu_fraction`.

Every selector-chain stage satisfies:

```text
effective_width <= authorized_stage_width <= B_cpu
```

Explicit workers are caps within the campaign budget. Task count, RAM/I/O admission, backend availability, an authoritative serial mutation boundary, or measured saturation may choose a smaller effective width.

### 4.2 Restore `DeterministicWorkQueue` capability

Restore/rebind the mature bounded queue against the **current** `StageResourceScope` API. Preserve:

- stable task identity/canonical order;
- bounded ready/in-flight/completed queues;
- RAM admission and persistent reservation accounting;
- deterministic ordered result commit where scientific reduction order matters;
- fail-fast worker exception propagation;
- cancellation/drain semantics;
- progress/heartbeat telemetry;
- process-wide native thread quarantine through the resource scope;
- no execution timing/completion order in scientific digests.

Do not create separate FEAS/MVIDX/REPAIR/MVQUAL schedulers when the shared queue suffices.

### 4.3 One parallel layer by default

Prefer broad independent outer tasks with inner tree/BLAS/OpenMP width 1. When a native MVSEL kernel is the measured dominant primitive, it may consume the authorized native/OpenMP width directly and Python candidate threading remains 1. Nested widths must be represented truthfully in `StageResourceScope` and cannot multiply beyond the budget.

## 7. MVSEL2 optimized production engine

The restoration target is the **final mature production engine**, not merely the scalar `target_multi_view_selector_v2.py` reference implementation.

### 7.1 One rank loop

Restore one `mvsel2_selection_engine`-equivalent owner for fresh and resumed selection. It delegates scientific scoring/mutation to the restored selector primitives and optimized exact kernels; it does not duplicate the D2 policy.

Fresh/resumed execution must share the same rank loop and yield identical rank history.

### 7.2 Phase-A locality kernel

Restore the mature locality-oriented Phase-A realization:

- family-major traversal;
- bounded dense FP64 contender-by-family scratch only where accepted;
- avoid per-candidate Python score dictionaries/boxed family tuples on the product path;
- avoid gratuitous widening of authenticated uint32 CSR rows;
- candidate/family read-only scoring may use native/OpenMP only inside exact independent rows;
- lexicographic filtering, canonical reduction order, authoritative candidate choice and mutation remain serial/canonical.

The failed Python candidate-thread design remains prohibited.

### 7.3 Phase-B cached-witness / lazy frontier

Restore:

- one FP64 representative term per witness, `weight/(multiplicity+1)`, as reconstructible execution cache;
- incremental updates only for witnesses touched by newly selected candidates;
- exact all-candidate Phase-B rebase at phase transition/rebuild;
- family-major rebase so a family mapping can be released after that family completes without G4c/G4d release/refault churn;
- outward-rounded conservative lazy bounds;
- bounded stale-candidate refresh batches;
- exact full-forward Python/NumPy oracle/fallback;
- no persisted candidate marginal authority or lazy heap as scientific state.

### 7.4 Native/OpenMP backend

Restore the private `_mvsel2_native`-equivalent row scorer through the package-wide native extension registry when the current build platform supports it.

Hard requirements:

- the scientific oracle remains Python/NumPy;
- the native reducer is bitwise-qualified on adversarial row lengths/values before parallel use;
- OpenMP distributes **independent candidate rows only**;
- a single row's FP64 reduction order matches the qualified NumPy authority;
- canonical family accumulation, lazy certification, contender filters, correlation/diversity/UID ties and state mutation remain serial Python authority;
- `workers=1` retains the exact qualified Python/NumPy path;
- `workers>1` requires a qualified native/OpenMP backend and never silently substitutes nondeterministic threading.

### 7.5 Dynamic real-graph native preflight

Restore the final accepted runtime meter rather than a fixed 4/8/16 cap:

- probe a bounded logarithmic-plus-budget set of widths ending at the authorized budget endpoint;
- measure the exact real-MVIDX family-row primitive;
- preserve the historical activation rule that parallel native execution is used only when its measured speedup clears the recovered accepted threshold (historically 1.75x in the V5 native redesign), unless R2 proves the exact final snapshot superseded that value;
- select the recovered final policy's economical width; do not hard-code the historical workstation's 8-worker result;
- otherwise use the exact qualified serial G4b/Python path.

Meter results are execution-only and never enter `pi_train` identity.

### 7.6 Restart/history

Restore MVSTATE2 plus authenticated rank-history/journal capability so resume does not rescore the selected prefix merely to reconstruct historical plan evidence. Heap/cache contents remain reconstructible. A corrupt/stale history cannot override MVSTATE2/prefix truth.

Revision-5/6 post-REPAIR state reconstruction rules remain binding.

## 8. REPAIR2 optimized execution

Restore the final accepted REPAIR2 execution lineage **inside the canonical REPAIR2 owner**.

### 8.1 State-invariant frontier factorization

Restore the accepted factorization of work that is invariant across removal proposals for one unchanged repair state:

- available candidate order;
- current objective/representative utility;
- hard-gain frontier where relevant;
- canonical bottleneck family;
- bottleneck coverage gains/frontier;
- total-coverage gains/frontier;
- exact no-proposal early-exit condition;
- small static metadata needed by downstream filters.

The context is execution-only and lexically/state-generation bounded. It cannot survive authoritative mutation.

Do not retain candidate-by-family or removal-by-candidate product-scale matrices.

### 8.2 Deterministic parallel proposal scoring

After factorization, restore immutable proposal evaluation through the shared `DeterministicWorkQueue`:

- every task reads one immutable pre-swap state/context;
- completion order is irrelevant;
- proposal results are assembled in canonical removal order;
- authoritative winner comparison is serial and uses the exact recovered objective/tie semantics;
- accepted deselect/select mutation is serial;
- queue/native worker width stays inside one `StageResourceScope`;
- no second campaign-side repair loop.

If Python proposal concurrency fails to scale on the current workload, do not add wrapper layers; retain the exact scalar/factorized path or recover the historically accepted native primitive only when the measured hotspot and exactness evidence justify it.

### 8.3 MVSTATE2 checkpoint-assisted repair

Restore the accepted checkpoint reuse rule:

- before first repair divergence, an authenticated selector checkpoint may avoid selected-prefix replay while the current rung's active shell is still repaired correctly;
- restoring a checkpoint at N must never imply that shell `[previous_rung,N)` has already been repaired;
- after the first accepted repair swap, later pure-selector checkpoints are ignored;
- missing/incompatible/corrupt state falls back to exact repaired-prefix/selected-prefix reconstruction;
- checkpoint assistance cannot change repair digest, rung evidence or swap trace.

This requirement composes with Revision 5's stronger rule that post-repair continuation for later MVSEL suffix generation is reconstructed from the final repaired prefix.
