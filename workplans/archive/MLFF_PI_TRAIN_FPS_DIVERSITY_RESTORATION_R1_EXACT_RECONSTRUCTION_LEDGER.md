### 8.2 Current explicit obligations and canonical composition

Current `ResolvedTargetSizePolicy.hard_support_obligations` remain current policy inputs. They are projected to exact current `P_train` and combined with automatic obligations by **scientific support locus**, not source ID.

For each source obligation define `L(o)` = support-locus identity, `A(o)` = exact current incidence, and `k(o)` = positive required minimum. Requirement strength is not part of locus identity.

Canonicalization is exactly:

```text
current automatic + current explicit
 -> project to exact current P_train
 -> remove retired-topology-only obligations
 -> normalize L(o), A(o), k(o), provenance
 -> fail on source-ID semantic collision
 -> group by L(o)
 -> require exact incidence equality inside each group
 -> k_canonical(L) = max k(o)
 -> assign one canonical ID per locus
 -> build MVIDX incidence/count authority
```

Therefore automatic `condition=A, minimum=1` plus explicit `condition_id=A, minimum=2` becomes one canonical minimum-2 obligation. Exact aliases and weaker same-locus records cannot increase hard gain. Same-locus incidence/applicability disagreement fails closed. Different scientific loci remain distinct even if incidence is identical.
