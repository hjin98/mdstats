This artifact is the repaired R3 D3 candidate after the first independent R3 review returned NO-PASS. It resolves the four blocking D3 findings without reopening accepted R1 D1/D2 or closed R2 dependency recovery.

It is still **proposed D3**. It does not self-accept architecture and does not authorize D4 product mutation. A fresh independent Protocol-6.3 D3 review must PASS this repaired candidate. After that PASS, the exact accepted architecture must be promoted into the canonical D3 Architecture Manual before D4 source mutation begins.

4. MVQUAL remains independent: its accepted predicates are recomputed from immutable TargetCoverageReference plus canonical obligation definitions; selector/repair counters are not an oracle and MVIDX is only an exact secondary cross-check where used.

## 3. Durable ownership constraints

1. `prepare` remains the only live-input/build/publication orchestration owner.
2. current prepared-generation storage plus CampaignStore remains the sole completed-generation publication/currentness/adoption architecture.
3. current P2 target-size policy remains the owner of configured candidate sizes, explicit hard-support policy inputs, and the public `TargetTrainingOrder`/qualification projection.
4. `TargetCoverageReference` is the sole selector-specific fitted numerical owner.
5. the canonical membership-obligation authority is a prepare-derived semantic projection of accepted D1/D2 and current P2 policy; no FEAS/MVIDX/MVSEL/REPAIR/MVQUAL component may independently redefine it.
6. NEIGHBOR1 owns the one exact candidate-witness neighborhood relation/build product for a selector generation.
7. MVIDX owns exact sparse forward/inverse representation and candidate-oriented consumption views of that relation plus canonical obligation incidence and current correlation-unit codes.
8. MVSEL2/REPAIR2 own construction of the one target-training order, not candidate sizes or target-size outcome ranking.
9. MVQUAL owns independent membership admissibility evidence only, not target-size error ranking.
10. P3 training/evaluation/reducer, post-selection CV/replay/production, and `pi_eval/M1/M2/M3` remain unchanged owners.
11. no selector-specific currentness database, prepared store, cleanup authority, target-size topology, provider registry, or migration subsystem may be added.

## 5. Selector-input and coverage-reference integration

Reuse current upstream source/frame/P1/P2 evidence identities and exact `P_train`. Restore only selector-input semantics needed by accepted family construction.

Historical DATA7 may contribute authenticated lineage/input semantics, but no historical DATA7 fitted metric/scaler/PCA/reference owner may coexist with `TargetCoverageReference`.

Selector preparation must never instantiate an unrelated foundation/profile provider solely to enrich coverage.

## 6. One canonical membership-obligation authority

### 6.1 Construction point

Construct the canonical obligation authority once after exact `P_train` and `TargetCoverageReference` are available, because automatic extent-side obligations depend on accepted coverage-reference extent semantics.

Inputs are:

```text
current P2 explicit hard-support requirements
+ accepted automatic current condition obligations
+ accepted current P1 correlation-unit obligations
+ accepted event/profile obligations when applicable
+ TargetCoverageReference extent-side obligations
```

Retired-topology-only obligations are excluded.

### 6.2 Required content

For each canonical obligation the authority binds at least:

```text
L(o)  canonical scientific support locus
A(o)  exact incidence set on current P_train
k(o)  effective positive minimum
applicability/provider identity
source aliases and source-local minima as provenance
governing current P2/policy identity
```

Canonicalization preserves accepted R1 semantics:

- source-local IDs are validated within explicit/automatic namespaces;
- locus identity is independent of source ID and minimum strength;
- equal accepted loci must have exact incidence agreement;
- same-locus accepted requirements compose with `k=max(k_i)`;
- aliases/minima are provenance, not additional hard-gain votes;
- incidence equality alone never establishes semantic aliasing;
- incompatible locus/applicability/provider/incidence projection fails closed;
- distinct scientific loci remain distinct even with identical incidence.

Exact type/class/hash encoding is D4-owned. D4 may merge this record into an existing truthful current record if doing so preserves one semantic owner; it may not duplicate the projection inside FEAS1 or MVIDX.

### 6.3 Dependency use

The same canonical authority is an explicit parent of:

- FEAS1 obligation support/capacity analysis;
- MVIDX canonical obligation sparse incidence;
- MVSEL2 hard-gain/count state;
- REPAIR2 hard deficit/hard-safe removal;
- MVQUAL independent prefix obligation recomputation;
- current P2 qualification projection.

MVIDX represents the authority efficiently; it does not define it.

## 7. Shared FEAS1 / NEIGHBOR1 construction

### 7.1 One exact geometry pass on the normal path

The mature recovered topology is preserved: the normal prepared path constructs the exact NEIGHBOR1 relation once and exposes both:

```text
TargetCoverageFeasibilityReport
TargetCoverageExactNeighborhoodStore
```

or exact-equivalent current products from one shared computation.

Architecturally:

```text
TargetCoverageReference + CanonicalMembershipObligationAuthority
        |
        v
shared FEAS1/NEIGHBOR1 builder
        |
        +--> FEAS1 support/fragility/capacity reduction
        |
        +--> authenticated exact NEIGHBOR1 forward relation
                 |
                 v
             MVIDX adoption/inversion/indexing
```

FEAS1 may perform reductions while the relation streams, as in the mature recovered capability. MVIDX must adopt/reuse the authenticated relation when lineage matches. The normal prepared path must not query the same exact geometry a second time merely because FEAS1 and MVIDX are distinct semantic consumers.

A rebuild of NEIGHBOR1 is permitted only when the required authenticated shared relation is genuinely absent, corrupt, incompatible, or intentionally invalidated as reconstructible cache. That is cache reconstruction, not a second current owner.

### 7.2 FEAS1

FEAS1 remains diagnostic/fail-closed. It consumes exact current `P_train`, `TargetCoverageReference`, the canonical obligation authority, and the shared NEIGHBOR1 relation/reduction state. It verifies domain/self-support consistency, fragility diagnostics, and conservative lower-bound/capacity evidence under current configured `N_max`.

FEAS1 cannot mutate target sizes, coverage thresholds, obligation minima, or create rescue candidates.

### 7.3 NEIGHBOR1/MVIDX resource contract

Restore or exactly preserve:

- accepted exact neighborhood boundary;
- canonical row/CSR ordering;
- file-backed/OOC large-array construction;
- bounded anonymous scratch and finalization memory;
- packed/shared durable roots or equal-or-stronger representation with mapped FD count O(1) in family count;
- forward-only restore for MVSEL2/REPAIR2 where witness roots are unnecessary;
- early reject/rebuild of obsolete per-family reconstructible layouts;
- disk/scratch/descriptor admission;
- transactional publication and cleanup of only attempt-owned partial state;
- exact MVIDX forward/inverse family incidence, canonical obligation incidence, and current correlation-unit codes.

No dense all-pairs product-scale relation or product-scale candidate-marginal authority is introduced.

## 8. MVSEL2 / REPAIR2 / complete-order integration

Restore one selector implementation with two exact views:

- scalar/full-forward reference oracle for bounded falsification/fallback;
- optimized certified-lazy production path.

The production path restores the mature witness-term cache, exact lazy bounds/certification, Phase-A locality behavior, and qualified native candidate-row acceleration before performance is judged. Parallelism may cover execution-independent rows/tasks only when it reproduces accepted binary64 semantics. Canonical contender filtering, tie logic, state mutation, repair mutation, and scientific ordering remain deterministic authority.

At every configured shell REPAIR2 may mutate only the active shell; lower configured prefixes are immutable. After the first accepted swap, all prefix-dependent selector continuation state derived from the pre-repair prefix is invalid. Reconstruct exact forward state from primitive authenticated sparse authority and the repaired prefix; rebuild lazy/native execution caches from that reconstructed state.

After the final configured shell, continue the same optimized exact MVSEL2 engine to `|P_train|`. No UID, condition-round-robin, scalar-only substitute, historical-Nmax stop, or alternate selector may complete the suffix.

## 9. Independent MVQUAL integration

MVQUAL consumes immutable `TargetCoverageReference`, canonical obligation definitions, exact configured prefixes, and the primitive identities needed to authenticate them.

It independently recomputes family coverage/extents and canonical obligation counts/effective minima. MVIDX may provide an exact secondary sparse cross-check, but MVSEL/REPAIR counters and cached selector state are never the sole oracle.

Progressive nested-rung optimization is allowed only with serial rung evolution inside each family/group state. Concurrency is across independent family/group state owners. Scientific reduction remains canonical and completion order cannot change content/digest.

Qualification projects into the existing P2/public owner. It has no target-size ranking or rescue authority.

## 10. Pre-adoption restart and recovery ownership

### 10.1 Owner and authority boundary

Expensive selector continuation produced before final prepared-generation adoption is owned by the existing `prepare` / prepared-storage lifecycle as **reconstructible build-cache/checkpoint state**. It is not a CampaignStore generation, target-order authority, or second currentness mechanism.

There are two distinct boundaries:

```text
pre-adoption prepare build state
    -> reconstructible, attempt/build-owned, never downstream-current

completed prepared generation
    -> immutable published products + manifest
    -> CampaignStore CAS adoption establishes currentness
```

### 10.2 Prospective build identity

Before reusable selector checkpoint state is admitted, `prepare` derives a deterministic prospective selector-build identity from all scientific parents/policies that can change continuation meaning, including at least:

- exact current `P_train`/split identity;
- selector-input/provider identities and fit domain;
- TargetCoverageReference identity;
- canonical obligation authority identity;
- exact NEIGHBOR/MVIDX identity or their reconstructible parent identities as appropriate to checkpoint level;
- MVSEL2 policy/version;
- configured ladder where repair shell position matters;
- REPAIR2 policy plus repaired-prefix/repair-plan identity after divergence.

Execution-only worker counts, queue timing, cache residency, and mmap path do not enter scientific build identity.

### 10.3 Attempt isolation and checkpoint publication

- mutable scratch is attempt-owned and never shared as authority;
- concurrent attempts may target the same prospective build identity but cannot write the same mutable scratch namespace;
- a reusable checkpoint/history object is published only at an authenticated crash-safe boundary, preferably immutable/content-addressed create-or-verify under the existing prepared storage root/lifecycle;
- publication of a reusable checkpoint does not make a prepared generation current;
- a consumer attempt validates exact build identity, schema/content integrity, prefix identity, and repair ancestry before reuse;
- stale, corrupt, incompatible, foreign-attempt mutable state is rejected/discarded or reconstructed exactly from primitive authority;
- file existence/path naming alone is never validity evidence.

### 10.4 Journals, retention, and recovery cost

Persist only minimal sufficient continuation state. Rank history/journal may be retained where it materially reduces restart cost or provides required diagnostics, but:

- replay/recovery cost is bounded;
- journals are compacted/snapshotted as needed rather than growing without bound;
- pre-repair history is diagnostic only after repaired-prefix divergence;
- zero-swap state remains reusable when its exact prefix/identity remains valid;
- post-repair checkpoints bind repaired-prefix/repair-plan identity;
- downstream select/CV/production never discover or consume pre-adoption selector checkpoints.

### 10.5 Finalization and cleanup

The final prepared manifest references only completed authenticated prepared products required by current consumption. CampaignStore remains the sole owner that makes a completed prepared generation current.

Cleanup/reclamation stays under existing prepared/storage ownership. It may remove only attempt/build-owned or unreachable reconstructible state after proving that no protected/current/restartable prepared generation references it. No selector-specific GC is introduced.
